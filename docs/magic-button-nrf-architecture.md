# Архитектура Magic Button на nRF52840

## Статус документа

Это описание актуальной реализации `Super Magic Button` на модифицированной
чёрной плате SuperMini nRF52840, совместимой по форм-фактору с nice!nano.
Источник правды прошивки — `firmware/magic-button-nrf/magic-button-nrf.ino`.

Поддержка XIAO и UICPal удалена. Упоминания этих плат в старом дневнике
энергопотребления являются только архивом экспериментов.

## Цели

- BLE HID-кнопка с одиночным, двойным и долгим нажатием.
- Настройка тем же web-конфигуратором по BLE или USB Serial.
- Быстрая реакция кнопки без постоянного активного опроса GPIO.
- Многолетняя работа от первичной литиевой батареи 3 В.
- System OFF с пробуждением и регистрацией нажатия одной кнопкой.

## Общая схема

```text
                       +-----------------------------+
CR2032/CR1220 -> B+ ---+-> VDDH ---+                 |
                       |           +-> VDD -> nRF52840
USB-C -----------------+-> D+ / D-                  |
                       |   VBUS detect               |
                       +-----------------------------+
                                  |
                         BLE HID / USB HID
                                  |
                         macOS / Windows / Linux

Browser configurator <- USB CDC or BLE Nordic UART Service
```

Батарея напрямую задаёт напряжение питания SoC. Преобразователя между батареей
и VDD нет.

## Аппаратная платформа

### Переделка силовой части

Штатная плата рассчитана на автоматический выбор USB/аккумулятора и питание
nRF52840 через VDDH/REG0. На протестированной ревизии этот тракт создавал
неприемлемый постоянный ток.

Обязательная переделка:

1. Удалить неисправный pull-up 5.6 кОм в цепи управления внешним VCC на P0.13.
2. Удалить диод силового тракта W5.
3. Удалить трёхвыводный силовой MOSFET.
4. Замкнуть площадки source и drain удалённого MOSFET.
5. Соединить B+ с площадкой SWD VDD.
6. Если USB будет доступен при установленной одноразовой батарее, удалить
   зарядник или гарантированно отключить его BAT от B+.

После переделки `B+`, `VDDH` и `VDD` соединены. nRF52840 работает в normal
voltage mode, а REG0 не участвует в питании.

Подробная карта переделки: `docs/supermini-nrf52840-low-power.md`.

### Ограничения питания

- Рабочее питание — первичная батарея около 3 В.
- CR2032 подходит напрямую.
- CR1220 электрически подходит, но её меньшая ёмкость и большее внутреннее
  сопротивление требуют проверки стартового провала напряжения.
- LiPo 4.2 В нельзя подключать напрямую к VDD. Для LiPo нужен внешний
  стабилизатор до 3.0–3.3 В либо другая силовая архитектура.
- После удаления силового USB-тракта USB используется для данных и определения
  VBUS. Для прошивки через USB батарея должна оставаться установленной.
- CR2032 и CR1220 нельзя заряжать.

### Назначение выводов

| Функция | nRF GPIO | Примечание |
|---|---:|---|
| Кнопка | P0.20 | Вход с pull-up, активный LOW |
| Возврат кнопки | P0.02 | Прошивка удерживает вывод в LOW |
| Status LED | P0.22 | Active HIGH, нужен последовательный резистор |
| External VCC cutoff | P0.13 | Удерживается в LOW после удаления pull-up |
| Плюс батареи | B+ / VDD / VDDH | Объединены аппаратными перемычками |
| Минус батареи | GND | Общая земля |

## Слои прошивки

```text
Button + power events
        |
Gesture state machine ----> HID action router ----> USB HID
        |                          |
        |                          +---------------> BLE HID
        |
Configurator protocol <---- USB CDC / BLE NUS
        |
LittleFS config storage

Battery SAADC -----------> BLE Battery Service
Power state machine -----> Active / Idle / System OFF
```

### Кнопка и пробуждение

В System ON не используется Arduino `attachInterrupt()`. На Adafruit nRF52 core
он выделяет high-accuracy GPIOTE IN channel, типичное потребление которого
оказалось близко к 18 мкА.

Текущий низкопотребляющий путь:

```text
P0.20 SENSE LOW
  -> GPIOTE EVENTS_PORT
  -> PPI channel 15
  -> EGU3 task 0
  -> SWI3_EGU3 IRQ
  -> FreeRTOS task notification
  -> updateButton()
```

После срабатывания SENSE временно отключается, чтобы удерживаемая кнопка не
создавала поток событий. После отпускания вход снова вооружается на LOW.

В System OFF P0.20 остаётся с `SENSE LOW`. Нажатие вызывает аппаратный reset,
прошивка читает GPIO latch и ставит одиночное нажатие в очередь. HID-отчёт
отправляется после восстановления защищённого BLE-соединения и подписки хоста.

### Распознавание жестов

- debounce: 10 мс;
- быстрое короткое нажатие: не более 100 мс;
- окно нескольких тапов: 250 мс;
- долгое нажатие: 600 мс;
- удержание 10 секунд: очистка BLE bonds;
- один тап: `singleTap`;
- два тапа: `doubleTap`;
- три быстрых тапа: открыть BLE-конфигурацию на 60 секунд;
- долгое нажатие: `longPress`.

Медленное одиночное короткое нажатие отправляется сразу после отпускания.
Быстрый тап ждёт окно 250 мс, чтобы отличить один тап от двойного и тройного.

### HID-транспорт

Если активна USB HID-сессия, действие отправляется через USB. Иначе используется
BLE HID. Поддерживаются:

- одноклавишный hotkey с модификаторами;
- Consumer Control usage.

Если BLE ещё не готов после пробуждения, жест хранится в очереди до 120 секунд
и повторяется каждые 200 мс. Для wake-жеста прошивка дополнительно ждёт пять
стабильных проверок готовности HID notification.

### BLE

Имя устройства: `Super Magic Button`.

Публикуются:

- HID keyboard и Consumer Control;
- Battery Service;
- Device Information Service;
- Nordic UART Service для конфигуратора.

`Bluefruit.begin(2, 0)` резервирует два peripheral connection slot. Обычно один
занят HID-соединением ОС. Тройной тап включает advertising на 60 секунд, чтобы
браузер мог открыть второе соединение для конфигурации, не разрывая HID.

После защищённого подключения прошивка запрашивает idle-параметры BLE:

- connection interval: 15 мс;
- slave latency: 15;
- supervision timeout: 4 с;
- TX power: -8 dBm.

### Конфигурационный протокол

USB CDC и BLE NUS несут одинаковые бинарные кадры:

```text
0x4F 0x53 | protocol_version:u8 | command:u8 | payload_len:u8 |
payload | crc8:u8
```

CRC-8 использует polynomial `0x07` и считается по version, command, length и
payload.

Основные команды:

| Команда | Код | Назначение |
|---|---:|---|
| GET_CONFIG | 0x01 | Прочитать конфигурацию |
| SET_CONFIG | 0x02 | Записать конфигурацию |
| RESET_CONFIG | 0x03 | Вернуть настройки по умолчанию |
| PING | 0x04 | Проверить устройство и его тип |
| CONFIG | 0x81 | Ответ с конфигурацией |
| ACK | 0x82 | Успешная запись |
| PONG | 0x84 | Ответ на PING |
| BUTTON_EVENT | 0x90 | Событие кнопки для USB-конфигуратора |
| ERROR | 0xFF | Ошибка кадра или команды |

Magic Button config занимает 14 байт:

```text
version:u8
singleTap:  type:u8 code:u16 modifiers:u8
doubleTap:  type:u8 code:u16 modifiers:u8
longPress:  type:u8 code:u16 modifiers:u8
crc:u8
```

Конфигурация хранится в Internal LittleFS в `/magic-button.cfg`. При изменении
формата необходимо одновременно повысить `CONFIG_VERSION` и обновить web-код.

## Энергетические состояния

| Состояние | Условие | BLE | Пробуждение |
|---|---|---|---|
| Active | нажатие, USB или недавняя активность | быстрый профиль | кнопка/протокол |
| Idle | 15 секунд бездействия | соединение сохраняется; advertising без соединения останавливается | PORT/SENSE |
| System OFF connected policy | 4 часа бездействия при BLE-соединении | соединение разрывается перед OFF | P0.20 SENSE LOW |
| System OFF disconnected policy | 1.5 часа без BLE | advertising остановлен | P0.20 SENSE LOW |

System OFF блокируется, пока нажата кнопка, ожидается multi-tap, есть
неотправленный жест или активна USB-сессия.

## Измерение батареи

После аппаратной переделки батарея напрямую питает VDD. SAADC измеряет
внутренний вход `PSELP=VDD` с internal reference 0.6 В и gain 1/6.

- измерение раз в 5 минут;
- offset calibration перед измерением;
- усреднение 16 выборок;
- калибровочная поправка текущего экземпляра: +200 мВ;
- внешнего резистивного делителя нет;
- процент для первичной батареи может только уменьшаться в рамках одного
  включения, чтобы шум не давал скачки обратно к 100%.

Текущая шкала рассчитана для CR2032:

| Напряжение | Заряд |
|---:|---:|
| 3.05 В | 100% |
| 3.00 В | 90% |
| 2.95 В | 75% |
| 2.90 В | 60% |
| 2.85 В | 45% |
| 2.80 В | 30% |
| 2.70 В | 15% |
| 2.60 В | 5% |
| 2.50 В | 0% |

Для CR1220 эта шкала является исходным приближением. Перед серией нужна
проверка полного разряда и стартовой просадки на реальном устройстве.

## Измеренное потребление

Для одного модифицированного SuperMini:

| Режим | До переделки | Сейчас |
|---|---:|---:|
| System ON idle, нижний уровень | около 1 мА | около 2.9 мкА |
| BLE event peak | — | до 120 мкА кратковременно |
| System OFF | около 0.42 мА | 0.4–0.5 мкА |

Последний переход с GPIOTE IN на PORT/SENSE снизил нижний уровень idle с
примерно 18 до 2.9 мкА, то есть в 6.2 раза. Полное снижение относительно
исходной платы составляет около 345 раз по idle floor и 840–1050 раз в
System OFF.

## Сборка и загрузка

```bash
npm run firmware:compile:magic:nrf
npm run firmware:export:magic:nrf
npm run firmware:upload:magic:nrf
```

Прямой target:

```bash
sh scripts/firmware.sh compile magic-button-nrf
```

FQBN: `adafruit:nrf52:mdbt50qrx`.

Если приложение не принимает DFU, дважды быстро замкнуть RESET и загрузить
сборку через появившийся UF2/DFU serial port.

## Проверка после сборки

1. Проверить одиночный, двойной и долгий жесты по BLE HID.
2. Проверить тройной тап и подключение конфигуратора вторым BLE-клиентом.
3. Проверить чтение и запись конфигурации.
4. Через 15 секунд проверить idle floor около единиц микроампер.
5. На временной сборке с 30-секундным OFF проверить 0.4–0.5 мкА.
6. Нажать кнопку в System OFF и убедиться, что устройство проснулось и
   зарегистрировало само нажатие.
7. Сравнить напряжение Battery Service с мультиметром на B+–GND.
